# Kiwi · 猕猴桃-你的文件助手 —— 发布与使用说明

一个纯网页版的文件互传工具：手机和电脑打开同一个网页，扫码就连上，
文字、网址、任意文件点对点直传。不用装 App，不用注册，不用自己的服务器。

---

## 一、把它发布到网上（免费，用你已有的 GitHub 仓库）

发布后你会得到一个固定网址，任何设备打开就能用。步骤：

1. 在电脑上打开 **GitHub Desktop**，把仓库 **Wanghaha0911/Kiwi** Clone 到本地
   （之前已经 Clone 过就直接打开那个文件夹，并先点一下 Fetch/Pull 拉最新）。
2. 把压缩包 `Kiwi-Website` 文件夹里的**全部内容**（index.html、app.js、style.css、
   libs 文件夹、README-Publish.md）复制到 Kiwi 仓库文件夹的**根目录**里，覆盖同名文件。
   注意：仓库根目录应该直接能看到 index.html，不要多套一层文件夹。
3. 回到 GitHub Desktop，左下角提交说明写一句如 `Kiwi website`，点 **Commit to main**，
   再点顶部 **Push origin** 把文件推上去。
4. 打开网页 github.com/Wanghaha0911/Kiwi → 顶部 **Settings** → 左侧 **Pages**：
   - Source 选 **Deploy from a branch**
   - Branch 选 **main**，文件夹选 **/ (root)**，点 **Save**
5. 等 1～3 分钟，刷新 Pages 设置页，顶部会出现你的网址：

   **https://wanghaha0911.github.io/Kiwi/**

   这就是 Kiwi 的家。电脑和手机都打开它就能用（手机建议用 Safari/Chrome 打开）。

> 以后想改版：重复第 2～3 步推一次，Pages 会自动更新，不用再动设置。

## 二、关于「网址直接叫 Kiwi」这件事

- 现在的免费网址是 `wanghaha0911.github.io/Kiwi/`：后半段就是 **Kiwi**，
  前半段是你的 GitHub 用户名，这是 GitHub 免费给的格式，没法再短。
- 真正只有一个词的网址（如 kiwi.com）属于**域名**：要花钱买、按年续费，
  而且 kiwi 相关的好域名基本已被注册或很贵。所以先用免费的这个，完全够用。
- 以后愿意花钱时，可以买一个自己的域名（如 kiwi-transfer.com 之类），
  在仓库 Settings → Pages → Custom domain 里填上，就能用自己的域名打开，
  功能和数据都不用动。这是可选升级，不是现在必须的。

## 三、怎么用：临时配对（默认）

1. **A 设备**（比如电脑）打开网址 —— 页面一打开，它自己就成为主机，
   屏幕中央直接是一张大二维码，不用点任何按钮。
2. **移动设备**用系统相机扫这张二维码 —— 会自动打开同一个网址并**自动连上 A**，
   不用再点加入。连上后就能：
   - 在下方对话框发文字/网址（网址会自动变成可点链接，带复制按钮）；
   - 点 📎 选任意文件发送（不限制大小和类型），发送前可以在「发送给」里
     选某一台设备，或选「所有设备」群发；
   - 每台设备都有自己的名字（可在设备列表里改名）、平台图标和专属颜色，
     谁发的消息、谁在线，一目了然。
3. **临时性的含义**：任意一方关掉页面/标签页，连接就断开；
   临时加入的设备下次要重新扫码；A 设备下次打开也是新二维码。
   这是默认行为，适合「就传这一次」。

> 多台设备可以扫同一个二维码加入同一个通道，大家在同一个设备列表里互相区分。

## 四、怎么用：信任设备（不想每次扫码）

信任是**双方各开一个开关**，缺一不可：

1. **A 设备（主机）**：在二维码下方打开 **「记住此通道」** 开关。
   之后 A 每次打开网页都是同一个通道、同一个二维码（关掉重开不变）。
2. **移动设备**：扫码连上后，在页面上方的连接横幅里打开 **「信任此设备」** 开关。
   这台手机就记住了 A。
3. 之后移动设备再打开网址时，会**先自动尝试重连 A**（约几秒）：
   - A 的页面正开着 → 直接连上，不用扫码；
   - A 没打开 → 页面会显示「对方未打开页面」，并打开手机自己的二维码，
     等 A 打开后在「已信任的设备」卡片里点 **重连** 即可。
4. **主机管理信任**：在 A 的设备列表里，可以给每台连过的设备点「信任此设备」。
   被信任的设备离线后仍会留在列表里（灰色显示「离线」），临时设备一断开就消失。
5. **取消信任**：手机端在连接横幅或「已信任的设备」卡片里点「忘记此设备」；
   主机端在设备列表点「取消信任」；主机也可以关掉「记住此通道」回到临时模式。
   取消后下次连接重新扫码。

**必须说清的一点**：信任只是「不用再扫码」，不是云端托管。
文件始终是两台设备**点对点直传**，不经过任何服务器保存，
所以不管临时还是信任，**传文件时双方页面都必须同时打开**，对方不在线就传不了。

## 五、其他说明与限制

- 传输走互联网（免费的 PeerJS 公共信令 + Google STUN 只负责帮两台设备牵线），
  不限距离；同一 Wi-Fi 下也会自动走更快的本地路径。公共信令是免费服务，
  自用足够，极偶尔抽风时刷新页面即可。
- 文件是分片流式发送的，发送方不挑大小和类型；但接收方最后会在浏览器内存里
  把文件拼成一个整体再提供下载，传几个 GB 的超大文件时接收设备内存要够。
- 主机页面关掉，整个通道就散了（没有服务器替你保管房间），临时设备需重新扫码，
  信任设备等主机重开后重连。
- 页面必须跑在 HTTPS 下才能用摄像头扫码和 WebRTC —— GitHub Pages 自带 HTTPS，
  按上面的方式发布就没问题。在电脑本机双击打开 index.html 是测不了连接的，
  请始终通过发布后的网址使用。
